# 周围环境：建图逻辑与画面

俯视图只用 RTAB-Map 已经发布的占据栅格 `/map`。彩色图、深度图和雷达留在建图节点内部，不直接画出来。点云和八叉树话题车上有，但一张俯视卡片用不到，也不再占用车端算力。

本文只定数据和画法。车从 A 开到 B 仍由导航栈执行，这里只负责把终点算进地图坐标。

## 数据

`/map` 的类型是 `nav_msgs/OccupancyGrid`。2026-10-28 在车上读到的一帧是：

| 字段 | 实测 |
| --- | --- |
| 分辨率 | 0.05 米/格 |
| 宽 × 高 | 164 × 183 格，约 8.2 米 × 9.2 米 |
| 原点 | 地图坐标系下 (-2.77, -4.50) 米，无旋转 |
| 格子取值 | -1 未知；0–100 为占据概率 |

格子按下标 `index = y * width + x` 排。格心在地图里的位置：

```
世界x = 原点x + (列 + 0.5) × 分辨率
世界y = 原点y + (行 + 0.5) × 分辨率
```

地图会随建图变大，原点和宽高都会变。画面每次都用这一帧自带的宽、高、分辨率和原点，不写死 164×183。

车的位置和朝向用 TF：`map` → `odom` → `base_footprint`。栅格大约一秒才变一次，车标要跟着里程计走，所以位姿单独送，不绑在地图帧上。

近处障碍用底盘已有的六路超声波 `ultrasonic_data_A` 到 `F`。每路是 `sensor_msgs/Range`：视场约 30°（0.52 弧度），盲区 0.02 米，最远 5.3 米。扇形只有在对应坐标系 `ultrasonic_data_*` 相对 `base_footprint` 的 TF 存在时才画。没有 TF 就不猜安装角。

## 从建图到画面

```
相机 / 深度 /scan /odom_combined
        │
        ▼
   车上 RTAB-Map          约 1 Hz，半个核，约 300 MiB
        │
        ▼
   /map  占据栅格
        │
        ▼
   车上桥接               原样转发格子和位姿，不再抽稀、不再画成三色 PNG
        │
        ▼
   浏览器画布             着色、车标、超声波、终点
```

一帧消息包含：

- 宽、高、分辨率、原点
- 格子数组，每个格子一个字节，-1 用 255 表示，0–100 原样保留
- 车在地图坐标系下的 x、y、朝向
- 六路超声波的距离；某一路没有 TF 或读数无效则缺省

当前地图大约 3 万字节，一秒一帧可以接受。宽或高超过 1500 格时，车上再按整数倍抽格，只为了控制传输，不改变颜色规则。

现在的实现把格子收成灰、白、黑并缩小到三分之一。概率和空地形状都丢了，车标和超声波也画不回去。新画法改由浏览器按原始概率上色。

## 画面

卡片保持现在的深色毛玻璃。地图在卡片内按比例放下，上下左右留出一圈空白，不拉伸。

画布的 y 轴向下，地图的 y 轴向上，绘制时按行倒过来。单元格用整数像素，整张图再缩放进卡片。

| 格子 | 颜色 |
| --- | --- |
| -1 未知 | `#1c1c1c`，和卡片融在一起，不再铺一块大灰板 |
| 0–49 空地 | `#2e2e2e` 到 `#3a3a3a`，概率越低越亮一点 |
| 50–100 障碍 | `#f4f1ec` 到 `#ff5a32`，概率越高越接近珊瑚橙 |

这样刚建出来的一小片地图是深底上的一块浅色可走区域，墙是亮线。未知区域不再看起来像一张灰纸。

叠在地图上的标记：

- **车**：珊瑚橙小三角，尖端朝 `base_footprint` 的前方。车体尺寸按 0.4 米 × 0.3 米画，只作示意。
- **超声波**：距离在 0.02–0.80 米之间时，沿该传感器朝向画一层半透明珊瑚橙扇形，半径等于测距。更远的不画，避免五米扇形盖住整张地图。读数超出量程或为无效值时不画。
- **终点**：用户点下的位置画一个珊瑚橙圆环，标为 B。车的当前位置就是 A，不在图上再点起点。
- **尚未收到地图**：卡片留空，不放占位图。

点一下空地或未知区域，把点击位置换回地图坐标：

```
列 = (点击的世界x - 原点x) / 分辨率
行 = (点击的世界y - 原点y) / 分辨率
```

点在障碍格（概率 ≥ 50）上不设终点。点在图外不设终点。设下的终点是地图坐标系里的一个点，朝向先与车当前朝向相同。真正发车不在这张图的绘制里完成。
